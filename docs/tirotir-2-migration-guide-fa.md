# راهنمای مهاجرت به Tirotir 2.0 candidate

این سند برای candidate شاخهٔ توسعهٔ `development/tirotir-2.0-20261017T110755Z` است و release عمومی محسوب نمی‌شود.

## ۱. تغییر arithmetic فشرده (KI-1)

در baseline تاریخی 1.1.0، lexer ممکن بود عبارت فشرده را به متن تفسیر کند:

```text
نسخهٔ 1.1.0: چاپ ۵-۳+۲-۱ → 5
نسخهٔ 2.0:   چاپ ۵-۳+۲-۱ → 3
```

این تغییر عمدی و breaking است. برنامه‌هایی که به خروجی تاریخی وابسته‌اند باید عبارت‌های حسابی را با فاصله و در صورت امکان با پرانتز بنویسند:

```text
چاپ ۵ - ۳ + ۲ - ۱
چاپ (۵ - ۳) + (۲ - ۱)
```

literal متنی سالم مانند `چاپ -سلام دنیا-` همچنان باید به‌عنوان متن حفظ شود.

## ۲. حداقل Python

candidate به Python `>=3.11` نیاز دارد، چون module loader از `tomllib` استفاده می‌کند. Python 3.9 و 3.10 در این candidate target اعلام‌شده نیستند.

## ۳. capabilityها

در candidate، `graphics`، `audio` و `gui` باید صریحاً مجاز شوند. برنامه‌ای که پیش‌تر بدون policy اجرا می‌شد ممکن است اکنون با خطای capability متوقف شود. این رفتار عمدی و امنیتی است.

`network` و `project-files` در این candidate primitive عمومی زبان ندارند. فعال‌کردن enum آن‌ها به‌تنهایی دسترسی شبکه یا فایل ایجاد نمی‌کند و نباید به‌عنوان sandbox کامل سیستم‌عامل تفسیر شود.

## ۴. Unicode و نیم‌فاصله

نیم‌فاصلهٔ U+200C در literalهای متنی حفظ می‌شود. در identifierها، U+200C داخلی طبق قرارداد normalization به underscore تبدیل می‌شود؛ برای نمونه:

```text
نام‌گذاری → نام_گذاری
```

## ۵. بررسی قبل از مهاجرت

پیش از انتقال پروژه:

1. full suite را اجرا کنید: `python3 -m pytest -q`؛
2. مثال‌های پروژه را با `tirotir check` بررسی کنید؛
3. برای graphics/audio/gui policy صریح تعریف کنید؛
4. مواردی را که از arithmetic فشرده استفاده می‌کنند بازبینی کنید؛
5. روی Python 3.11 یا 3.12 نصب پاک انجام دهید.

## ۶. وضعیت پشتیبانی

این candidate روی Linux و Python 3.11/3.12 در CI بررسی شده است. اجرای واقعی Windows، macOS، VS Code، پخش صوت سخت‌افزاری و desktop GUI در این مرحله تأیید نشده‌اند.
