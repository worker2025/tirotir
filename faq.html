۱ شروع سریع

۱) روی Windows چه چیزی لازم است؟

برای کاربر نهایی: Setup مستقل Tirotir نیاز به Python، pip، Git یا PyInstaller ندارد. کافی است بستهٔ نصب ویندوز را از پوشهٔ install/ مخزن دریافت و اجرا کنید.

برای توسعه‌دهنده: می‌توان از Python و نصب بستهٔ پروژه استفاده کرد:

python -m pip install .
tirotir version
۲) چگونه فایل EXE بسازم؟

Tirotir Builder یک ابزار گرافیکی است که به شما امکان می‌دهد یک فایل .t را انتخاب کرده و خروجی اجرایی Windows (EXE) بسازید. این ابزار از PyInstaller در پشت صحنه استفاده می‌کند.

توجه: خروجی Builder را با «کامپایلر بومی» اشتباه نگیرید؛ این فرآیند بسته‌بندی (packaging) است، نه ترجمه به کد ماشین.
۳) چرا Graphics، Audio یا GUI در شبیه‌ساز مرورگر کامل نیست؟

آزمایشگاه مرورگر یک شبیه‌ساز آموزشی client-only است و خروجی متنی توصیفی می‌دهد. اجرای واقعی SVG، WAV و Tkinter در runtime نصب‌شدهٔ Tirotir و افزونهٔ VS Code انجام می‌شود. بنابراین اگر در مرورگر گرافیک یا صدا را کامل ندیدید، به معنای نبود قابلیت در نسخهٔ اصلی نیست.

۲ آشنایی با تیروتیر

۴) تیروتیر چیست؟
تیروتیر یک زبان برنامه‌نویسی متنی با واژگان و شناسه‌های فارسی است. کاربر برنامه‌ای با پسوند رسمی .t می‌نویسد و مفسر تیروتیر آن را اجرا می‌کند. این زبان برای یادگیری مفاهیم برنامه‌نویسی، آزمایش ایده‌ها و ساخت برنامه‌های کوچک و خلاقانه طراحی شده است. امکاناتی برای محاسبه، ورودی و خروجی، گرافیک SVG، تولید صدای WAV و رابط گرافیکی پایه نیز در مخزن وجود دارد.
۵) چرا تیروتیر «زبان برنامه‌نویسی» است و فقط مجموعه‌ای از دستورها یا ترجمهٔ فارسی Python نیست؟
چون رفتار یک زبان را فقط نام کلیدواژه‌ها تعیین نمی‌کند. تیروتیر قواعد نوشتار (نحو)، تفسیر عبارت‌ها، متغیر و دامنه، کنترل جریان، تابع، داده‌ها، خطاها و روش اجرای مشخص خودش را دارد. پیاده‌سازی آن شامل توکن‌ساز، تجزیه‌گر، AST و مفسر است. دستورها به کد Python ترجمه نمی‌شوند تا Python اجرا کند؛ مفسر تیروتیر مستقیماً ساختار و رفتار برنامه را مدیریت می‌کند.
۶) آیا تیروتیر از زبان دیگری ساخته شده است؟
بله، از دید پیاده‌سازی، مفسر و ابزارهای فعلی عمدتاً با Python نوشته شده‌اند. این موضوع به‌تنهایی به این معنی نیست که زبان تیروتیر «زیرمجموعهٔ Python» یا transpiler آن است. زبان‌های زیادی با زبان دیگری پیاده‌سازی می‌شوند (زبان میزبان یا Host Language). باید بین «زبانی که برنامه‌نویس با آن کد می‌نویسد» و «زبانی که مفسر با آن ساخته شده» تفاوت قائل شد.
۷) اگر مفسر با Python نوشته شده، چرا خود برنامهٔ تیروتیر Python محسوب نمی‌شود؟
چون کد اجراشونده در فایل .t قواعد تیروتیر را دنبال می‌کند (مثل چاپ، بگذار). مفسرِ Python-نوشته این متن را می‌خواند، به اجزای قابل‌فهم تبدیل می‌کند و طبق معنای تیروتیر اجرا می‌کند.
۷‌ب) آیا تیروتیر فقط یک کتابخانهٔ Python است؟

خیر. تیروتیر از نظر نحو، فایل منبع، مدل اجرا و ابزارهای زبانی یک زبان برنامه‌نویسی متنی و مفسری مستقل است؛ Python زبان پیاده‌سازی فعلی مفسر و runtime تیروتیر است.

برنامه‌نویس کد تیروتیر را با نحو مخصوص خودش و در فایل‌های .t می‌نویسد، نه در فایل‌های .py. این کد با CLI و مفسر خود تیروتیر اجرا می‌شود: 

tirotir run program.t

تیروتیر lexer، parser، AST، تحلیل معنایی، قراردادهای اجرایی و interpreter خودش را دارد. کد تیروتیر به‌صورت ساده به Python ترجمه نمی‌شود تا Python آن را اجرا کند؛ مفسر تیروتیر ساختار و معنای برنامه را طبق قواعد خود زبان مدیریت می‌کند.

البته این ادعا به معنی مستقل‌بودن کامل از Python در سطح نصب و پیاده‌سازی نیست: runtime فعلی تیروتیر با Python پیاده‌سازی شده و برای اجرا به Python 3.11+ نیاز دارد.

خلاصه: تیروتیر یک زبان برنامه‌نویسی است که interpreter آن با Python نوشته شده؛ Python زبان میزبان تیروتیر است، نه زبان برنامهٔ کاربر.
۸) آیا تیروتیر کامپایلر دارد؟
در نسخهٔ 1.1.0 مسیر اصلی اجرا مفسری (interpreted) است، نه کامپایل به کد ماشین. ابزارهایی مانند run، check و ast وجود دارند. قابلیت ساخت EXE در پروژه به بسته‌بندی (Builder) مربوط است و نباید آن را با کامپایلر بومی یکی دانست.
۹) تیروتیر برای چه کسانی مناسب است؟
برای فارسی‌زبانانی که می‌خواهند با مفاهیم پایه (متغیر، شرط، حلقه، تابع) شروع کنند؛ برای مدرس و دانشجو جهت نمایش مفاهیم محاسباتی؛ و برای ساخت نمونه‌های کوچک آموزشی، گرافیکی، صوتی یا GUI پایه. برای سامانه‌های بزرگ یا نرم‌افزارهای production-critical باید محدودیت‌های نسخهٔ فعلی را در نظر گرفت.
۱۰) هدف تیروتیر جایگزین‌کردن Python، Java یا C++ است؟
از اطلاعات نسخهٔ فعلی چنین ادعایی برنمی‌آید. هدف برجستهٔ پروژه، برنامه‌نویسی فارسی و تجربهٔ آموزشی/خلاقانه است. ابزارهای زبان‌های بالغ‌تر، کتابخانه‌ها و کارایی آن‌ها را نباید با دامنهٔ فعلی تیروتیر یکسان فرض کرد.
۱۱) نام و پسوند فایل آن چیست؟
نام لاتین پروژه Tirotir و نام فارسی آن تیروتیر است. پسوند رسمی برنامه‌ها .t است. پسوند قدیمی .tirotir برای سازگاری با فایل‌های قبلی نگه داشته شده است.

۳ ساختار و نحو زبان

۱۲) یک برنامهٔ ساده در تیروتیر چه شکلی است؟ 
چاپ -سلام دنیا-

برای تعریف متغیر و شرط:

بگذار سن برابر ۲۰

اگر سن بزرگتر یا مساوی ۱۸
    چاپ -بزرگسال-
وگرنه
    چاپ -نابالغ-
۱۳) چرا دستورها فارسی‌اند؟
برای پایین‌آوردن مانع زبانی در شروع برنامه‌نویسی و فراهم‌کردن راهی برای نوشتن مثال‌ها و آموزش به فارسی. فارسی‌بودن واژگان، جایگزین مفاهیم CS یا استانداردهای فنی نیست؛ هدف این است که زبانِ بیان الگوریتم برای مخاطب فارسی‌زبان آشناتر باشد.
۱۴) آیا فقط حروف فارسی قابل استفاده‌اند؟
خیر. مخزن از شناسه‌های Unicode پشتیبانی می‌کند و ارقام فارسی و لاتین را می‌پذیرد. در پیاده‌سازی، بعضی صورت‌های Unicode نرمال می‌شوند (مثلاً «ي» به «ی»، «ك» به «ک»). بهتر است در یک پروژه شیوهٔ نوشتن نام‌ها را یکدست نگه دارید.
۱۵) بلوک‌های شرط، حلقه و تابع با چه چیزی مشخص می‌شوند؟
با تورفتگی (indentation)، نه آکولاد. طبق تصمیم طراحی پروژه، تورفتگی استاندارد چهار فاصله است و تورفتگی ناسازگار خطا می‌دهد: 
تکرار ۳ بار
    چاپ -درود-
۱۶) متن یا رشته چگونه نوشته می‌شود؟
در نحو فعلی، متن معمولاً بین دو خط تیره قرار می‌گیرد: -سلام-. اگر خود متن خط تیره داشته باشد، می‌توان آن را با \- گریز داد. این نحو ساده است، اما ممکن است در بعضی عبارت‌ها با عملگر تفریق اشتباه‌پذیر باشد.
۱۷) کامنت چطور نوشته می‌شود؟
کامنت با # آغاز می‌شود و آن بخش از خط برای اجرا نیست: 
# این یک توضیح برای خواننده است
چاپ -سلام-
۱۸) چه نوع داده‌هایی دارد؟
عدد، متن، مقدار منطقی (درست و نادرست)، مقدار تهی (تهی)، فهرست و فرهنگ. تیپ‌دهی پویا است (هنگام نوشتن اعلان نوع اجباری نیست).
۱۹) متغیر و ثابت چگونه تعریف می‌شوند؟
متغیر با بگذار و ثابت با ثابت تعریف می‌شود: 
بگذار امتیاز برابر ۱۰
ثابت سقف برابر ۱۰۰
تغییر ثابت باید با خطا روبه‌رو شود.
۲۰) چه عملگرهایی وجود دارند؟
عملگرهای عددی اصلی +، -، *، / و %. مقایسه با == و >= یا صورت‌هایی مانند بزرگتر یا مساوی. منطق با و، یا و نه.
۲۱) شرط و حلقه چه دستورهایی دارند؟
شرط‌ها با اگر، وگرنه اگر و وگرنه. حلقه‌های برای، تاوقتی و تکرار ... بار. بیرون برای خروج از حلقه و ادامه برای تکرار بعدی.
۲۲) تابع، پارامتر و بازگشت مقدار چگونه‌اند؟
تابع با تابع تعریف می‌شود: 
تابع مربع با عدد
    بازگردان عدد * عدد

چاپ مربع با ۵
۲۳) دامنه یا scope چیست و آیا تیروتیر دارد؟
بله. مفسر محیط متغیرها و محیط والد برای تابع دارد و semantic analyzer نیز جدول نماد و scopeهای تابع را مدل می‌کند. این مفهوم برای فهم متغیر محلی، سراسری و خطای نام تعریف‌نشده مهم است.
۲۴) ورودی و خروجی چه هستند؟
چاپ برای خروجی و بخوان برای خواندن ورودی استفاده می‌شود. رابط prompt و اعتبارسنجی را باید خود برنامه مدیریت کند.
۲۵) فهرست و فرهنگ چه کاربردی دارند؟
فهرست برای نگهداری چند مقدار به ترتیب و فرهنگ برای نگهداری مقدارهایی با کلید نام‌دار. توابعی مانند طول، افزودن، حذف، به_عدد و به_متن در مستندها معرفی شده‌اند.

۴ معماری و اصطلاحات فنی

۲۶) برنامهٔ تیروتیر چگونه از متن به اجرا می‌رسد؟ 
متن برنامه
   ↓
نرمال‌سازی و توکن‌سازی (Lexer/Tokenizer)
   ↓
تجزیهٔ نحوی (Parser)
   ↓
درخت نحو انتزاعی (AST)
   ↓
تحلیل معنایی و تشخیص خطاهای قابل‌بررسی
   ↓
مفسر و سرویس‌های runtime
   ↓
خروجی، اثر گرافیکی/صوتی یا خطا
۲۷) Lexer یا Tokenizer چیست؟
بخشی است که متن خام را به واحدهای کوچک‌تر معنادار، یعنی توکن (token)، تبدیل می‌کند (واژه، عدد، رشته، عملگر، نشانهٔ تورفتگی).
۲۸) Parser و AST چه می‌کنند؟
Parser توکن‌ها را طبق قواعد زبان به ساختار برنامه تبدیل می‌کند. AST (درخت نحو انتزاعی) نمایش ساختاری برنامه است. فرمان tirotir ast می‌تواند نمایش JSON درخت را نشان دهد.
۲۹) تحلیل نحوی و تحلیل معنایی چه تفاوتی دارند؟
تحلیل نحوی می‌پرسد آیا ساختار جمله طبق دستور زبان معتبر است. تحلیل معنایی می‌پرسد آیا ساختار از نظر معنا قابل‌قبول است (مثلاً آیا نام متغیر تعریف شده است).
۳۰) Interpreter یا مفسر چیست؟
برنامه‌ای است که ساختار برنامهٔ تیروتیر را می‌خواند و دستوراتش را اجرا می‌کند. مفسر فعلی محیط متغیرها، توابع، شرط‌ها، حلقه‌ها و فراخوانی سرویس‌هایی مانند گرافیک و صدا را مدیریت می‌کند.
۳۱) Runtime چیست؟
زمان‌اجرا (runtime) محیط و سرویس‌هایی است که اجرای برنامه به آن‌ها متکی است: مفسر، محیط متغیرها، توابع داخلی، خطاها و backendهایی مانند SVG یا Tkinter.
۳۲) Diagnostic، Source Span و Symbol Table یعنی چه؟
  • Diagnostic: گزارش ساختاریافتهٔ خطا/هشدار با کد، شدت، پیام و گاهی پیشنهاد اصلاح.
  • Source span: بازه یا محل وقوع یک توکن/خطا در متن منبع (خط و ستون).
  • Symbol table: جدولی از نام‌های تعریف‌شده مثل متغیر، پارامتر و تابع و scope مربوط به آن‌ها.
۳۳) CLI، REPL و formatter چیستند؟
  • CLI: ابزار خط فرمان (مثل run، check).
  • REPL: محیط تعاملیِ خواندن، اجرا و نمایش نتیجه، دستوربه‌دستور.
  • Formatter: ابزار یکدست‌کردن قالب کد (فرمان format).
۳۴) افزونهٔ VS Code چه امکاناتی دارد؟
شناسایی فایل، syntax highlighting و فرمان‌های اجرا/بررسی/نمایش AST. همچنین خروجی RTL و نمایش صحنهٔ زنده در WebView. این افزونه هنوز یک محیط توسعهٔ کامل با LSP، تکمیل هوشمند پیشرفته یا debugger حرفه‌ای نیست.

۵ قابلیت‌های فعلی، نصب و امنیت

۳۵) چگونه تیروتیر را نصب یا امتحان کنم؟ 
python -m pip install .
tirotir version
tirotir run hello.t

مخزن بسته‌های Windows و افزونهٔ VS Code را در مسیر install/ فهرست می‌کند. برای مرور کد، پوشهٔ examples2/ را ببینید.

۳۶) فرمان‌های اصلی خط فرمان کدام‌اند؟ 
tirotir version
tirotir run hello.t
tirotir check hello.t
tirotir ast hello.t
tirotir format hello.t
tirotir repl
۳۷) آیا گرافیک دارد؟
بله، دستورات گرافیکی پایه وجود دارد و مسیر گزارش‌شدهٔ نسخهٔ 1.1.0 صحنه را به SVG تبدیل می‌کند (مربع، مستطیل، مثلث، دایره و حرکت قلم). این قابلیت را با موتور بازی اشتباه نگیرید.
۳۸) آیا انیمیشن یا ساخت بازی دارد؟
در نسخهٔ 1.1.0، انیمیشن کامل و runtime بازی‌سازی کامل قابلیت تثبیت‌شده محسوب نمی‌شوند. نقشهٔ راه دربارهٔ event runtime صحبت می‌کند، اما نباید آن را آمادهٔ تولید فرض کرد.
۳۹) آیا صدا و موسیقی دارد؟
مخزن تولید توالی نت و فایل WAV را پشتیبانی می‌کند. نت‌های فارسی مانند دو، ر، می، فا و سل به WAV تبدیل می‌شوند و برای ملودی‌های کوتاه امکان پخش ترتیبی وجود دارد. پخش واقعی به ابزار/سیستم‌عامل وابسته است و ممکن است در محیط headless کار نکند.
۴۰) آیا رابط گرافیکی (GUI) دارد؟
یک backend پایهٔ GUI بر مبنای Tkinter وجود دارد (پنجره، label، button، ورودی، چک‌باکس، فهرست). اجرای GUI به محیط desktop نیاز دارد. callback کامل و event system در سطح زبان در وضعیت فعلی تضمین نشده‌اند.
۴۱) آیا برنامهٔ تیروتیر می‌تواند Python، shell یا شبکه را آزادانه اجرا کند؟
خیر؛ طراحی پروژه بر پرهیز از eval/exec عمومی، import آزاد Python و دسترسی بی‌قید به شبکه تأکید دارد. بااین‌حال این طراحی به معنی sandbox امنیتی کامل در سطح سیستم‌عامل نیست.
۴۲) Capability-based چیست؟
یعنی برنامه فقط در صورت فعال‌بودن مجوز مشخص به یک سرویس بیرونی دسترسی بگیرد (مثل graphics، audio). این مدل کمک می‌کند سرویس‌ها از هسته جدا شوند. اجرای قابلیت‌ها باید از Runtime API و Capability Registry عبور کند.
۴۳) پروژهٔ چندفایلی و ماژول دارد؟
مخزن tirotir.toml، loader و module graph را معرفی می‌کند. import به شکل وارد کن -نام- است. اما package manager خارجی وجود ندارد.
۴۴) آیا تیروتیر در Windows، Linux و macOS کار می‌کند؟
کد Python و ابزارهای خط فرمان با هدف قابل‌حمل‌بودن عرضه شده‌اند. برخی پذیرش‌های واقعی desktop، GUI و ساخت EXE نیازمند آزمون دستی/بومی هستند.
۴۵) چند تست دارد؟ آیا این FAQ تست‌ها را اجرا کرده است؟
گزارش آمادگی انتشار برای نسخهٔ 1.1.0، ۲۴۴ تست موفق را گزارش می‌کند. در محیط تهیهٔ این FAQ ماژول pytest نصب نبود، بنابراین این عدد مستقل بازاجرا نشد.
۴۶) آیا می‌توان از تیروتیر برای محصول تجاری استفاده کرد؟
مجوز مخزن MIT اعلام شده است (permissive). بااین‌حال پیش از توزیع تجاری، متن LICENSE همان نسخه را بررسی کنید. این مجوز هیچ تضمینی دربارهٔ پشتیبانی یا کیفیت production ایجاد نمی‌کند.

۶ محدودیت‌ها و مسیر آینده

۴۷) کدام قابلیت‌ها در نسخهٔ 1.1.0 کامل نیستند؟
مدل شیء/کلاس و وراثت، سیستم نوع‌دهی کامل، exception model عمومی، generator، async/await، انیمیشن کامل، event system/callbackهای کامل GUI، LSP کامل، DAP و debugger حرفه‌ای.
۴۸) معماری ۲٫۰ شامل چه بخش‌هایی است؟

بخش‌های تثبیت‌شده در نقشهٔ معماری ۲٫۰:

Contract Freeze Diagnostic Semantic Layer SymbolTable Module System Sandbox Path تشخیص چرخهٔ وابستگی

بخش‌های نقشهٔ راه بعدی:

Event Runtime Object Model LSP Debugger
۴۹) LSP و DAP چه هستند و چرا اهمیت دارند؟
LSP راه استاندارد ارتباط editor با سرویس تحلیل زبان است (تکمیل کد، خطایابی لحظه‌ای). DAP استاندارد ارتباط editor با debugger است. این‌ها در مخزن به‌عنوان کار آینده/محدودیت ذکر شده‌اند.
۵۰) آیا نسخهٔ 2.0 آماده یا تضمین‌شده است؟
خیر، نقشهٔ راه 2.0 سند برنامه‌ریزی معماری است، نه اعلام آمادگی. هر مورد را باید تا زمان merge و release، «پیشنهاد یا کار آینده» دانست.
۵۱) فازهای بعدی توسعه چه می‌توانند باشند؟
تثبیت قراردادها و diagnostics، تکمیل semantic analysis و formatter، پروژه و ماژول، event loop، طراحی object model، debugger/LSP و سرویس‌های استاندارد.
۵۲) آیا باید مفسر را با transpiler یا VM جایگزین کرد؟
در مستندهای طراحی، مفسر مستقیم به‌عنوان مسیر ساده و مناسب آموزش حفظ شده است. transpiler به Python می‌تواند دسترسی را آسان‌تر کند ولی مرز امنیت و خطاها را پیچیده می‌کند.

۷ پرسش‌های مناسب برای مصاحبهٔ فنی

۵۳) اگر بپرسند «زبان برنامه‌نویسی دقیقاً از چه ساخته می‌شود؟» چه پاسخی بدهیم؟
زبان دست‌کم قرارداد قابل مشاهده‌ای از نحو و معنا دارد؛ برای اجرا هم پیاده‌سازی لازم است. در تیروتیر متن به توکن‌ها تبدیل، با parser به AST تبدیل، و توسط مفسر اجرا می‌شود.
۵۴) «آیا هر زبان با زبان دیگری ساخته می‌شود؟»
خیر. یک زبان می‌تواند با زبان دیگری پیاده‌سازی شود، با خودش پیاده‌سازی شود (self-hosting)، یا با ترکیبی از زبان‌ها و ابزارها ساخته شود. تیروتیر فعلاً عمدتاً با Python پیاده‌سازی شده است.
۵۵) «آیا تیروتیر فقط syntax sugar روی Python است؟»
در نسخهٔ حاضر کد تیروتیر مستقیماً به Python transpile نمی‌شود؛ پیاده‌سازی یک parser/AST و interpreter برای اجرای خود نحو تیروتیر دارد.
۵۶) «آیا زبان کامپایل‌شده سریع‌تر از مفسری است؟»
این مقایسه به پیاده‌سازی، workload و بهینه‌سازی وابسته است. تیروتیر 1.1.0 مسیر مفسری دارد و برای آموزش و پروژه‌های کوچک طراحی شده است.
۵۷) «تیروتیر static typing دارد یا dynamic typing؟»
در استفادهٔ فعلی، اعلان نوع اجباری نیست و داده‌ها در زمان اجرا مدیریت می‌شوند؛ پس باید آن را پویا (dynamic) توصیف کرد.
۵۸) «آیا مفسر sandbox امنی است؟»
طراحی، دسترسی آزاد به shell و Python را محدود می‌کند؛ اما خود مخزن هشدار می‌دهد که این sandbox کامل در سطح سیستم‌عامل نیست.
۵۹) «چطور ثابت می‌کنید که تیروتیر یک زبان است؟»
به‌جای تکیه بر نام، شواهد فنی را نشان می‌دهیم: دستور زبان، lexer/parser، AST، semantics و interpreter مستقل، ابزار اجرا/بررسی و تست‌های زبان.
۶۰) «بزرگ‌ترین trade-off طراحی تیروتیر چیست؟»
سادگی و دسترس‌پذیری برای شروع در برابر قابلیت‌ها و اکوسیستم پیشرفته. نحو فارسی شروع را آسان می‌کند، اما کارایی و ابزارهای IDE نیازمند کار بیشترند.
۶۱) «چطور دربارهٔ قابلیت‌های آینده پاسخ دقیق بدهیم؟»
وضعیت را به سه دسته تقسیم کنید: پیاده‌سازی و مستندشده در نسخهٔ فعلی، نمونه/آزمایشی با محدودیت مشخص، و طرح یا نقشهٔ راه.

۸ واژه‌نامهٔ کوتاه

اصطلاح معنی ساده
زبان میزبان (Host language)زبانی که مفسر یا کامپایلر با آن پیاده‌سازی شده (در تیروتیر عمدتاً Python).
مفسر (Interpreter)برنامه‌ای که کد زبان را می‌خواند و طبق معنای آن اجرا می‌کند.
کامپایلر (Compiler)برنامه‌ای که کد را به نمایش/کد دیگری برای اجرا تبدیل می‌کند.
توکن (Token)جزء کوچک معنادار متن برنامه، مانند عدد، واژه یا عملگر.
Lexer/Tokenizerبخش تشخیص‌دهندهٔ توکن‌ها از متن خام.
Parserبخش بررسی ترتیب توکن‌ها طبق قواعد نحوی و ساختاردهی برنامه.
ASTدرخت نحوی انتزاعی؛ نمایش ساختاری برنامه برای ابزار و مفسر.
Semantic analysisبررسی معنای ساختار، مانند نام تعریف‌نشده یا استفادهٔ نامعتبر.
Scopeمحدوده‌ای که در آن نام متغیر/تابع قابل دسترسی است.
Symbol tableداده‌ساختاری برای ثبت نمادها، نوع نماد و scope آن‌ها.
Runtimeمحیط و سرویس‌های لازم برای اجرای برنامه.
CLIرابط خط فرمان برای اجرا و ابزارهای زبان.
REPLمحیط تعاملی برای اجرای دستورها به‌صورت زنده.
Moduleفایل/واحدی از برنامه که در پروژهٔ چندفایلی به آن ارجاع داده می‌شود.
Capabilityمجوز کنترل‌شده برای دسترسی به سرویس بیرونی مانند GUI یا graphics.
Backendپیاده‌سازی زیرساختی یک سرویس؛ مثلاً SVG برای رسم یا Tkinter برای پنجره.
LSPپروتکل استاندارد ارتباط editor با سرویس زبان.
DAPپروتکل استاندارد ارتباط editor با debugger.
Unicodeاستاندارد نمایش حروف و نویسه‌های زبان‌های مختلف.
RTLراست‌به‌چپ؛ جهت نمایش متن.
Sandboxمحدودسازی محیط اجرا؛ قدرت آن به سطح پیاده‌سازی و جداسازی سیستم‌عامل وابسته است.
